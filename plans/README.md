# Plans

Plans describe intended work before implementation. They should be specific
enough that another engineer or agent can carry out the change without guessing
the important decisions.

Use plans for meaningful changes that affect behavior, architecture, operating
policy, or review scope. Small documentation edits may not need a full plan.

Recommended filename format:

```text
YYYY-MM-DD-short-name.md
```

See `../examples/plans/example-initiative-plan.md` for a reusable format.
